# Czech·Swiss Schedule Detail Enrichment Design

## Goal

체코·스위스 허니문 가이드의 현재 일정, 예약, 숙소, 지도, 사진을 삭제하거나 재배치하지 않고 일정표 상세창과 일부 짧은 본문을 초행자용 여행 가이드 수준으로 보강한다. 변경 후 웹·앱 모드, 지도, 캐시, 모바일 화면을 다시 검증하고 발견된 오류를 같은 작업에서 수정한다.

## Approved Direction

권장안 1번을 적용한다.

- 화면의 일정표 셀은 현재처럼 짧게 유지한다.
- 일정표 셀을 누르면 열리는 기존 상세창에 행동 가능한 설명을 추가한다.
- 본문은 실제 설명 밀도가 낮은 항목만 선별 보강한다.
- 날짜, 예약 시간, 확정 숙소, 확정 이동 순서와 지도 번호는 바꾸지 않는다.
- `이건 엑셀에서 가져왔습니다`, `엑셀 기준`, `스프레드시트에서 가져옴`과 같은 출처 노출 문구는 가이드 본문과 상세창에 넣지 않는다.

## Current Evidence

- 체코 일정표에는 `.calendar-event`가 46개 있으며 4개만 `data-detail`을 가지고 있다. 42개는 상세창의 세부 구간이 비어 있거나 일반적인 요약으로 끝난다.
- 스위스 일정표에는 `.calendar-event`가 39개 있으며 14개만 `data-detail`을 가지고 있다. 25개는 상세창의 세부 구간이 비어 있거나 일반적인 요약으로 끝난다.
- `assets/schedule-detail.js`는 `data-detail`을 `|`로 나눠 상세창의 `세부 구간` 목록으로 표시한다. 기존 모듈의 동작은 유지하고 콘텐츠 속성을 완성하는 것이 우선이다.
- 393×852와 402×874에서 체코·스위스의 `?view=web`, `?view=app`은 가로 문서 넘침이 0이며 동일 HTML 본문을 공유한다.
- 현재 지도 연결은 체코 7개, 스위스 6개, 이탈리아 7개로 총 20개이며 장소 키, 좌표, 경로 참조, HTML ID 중복 오류는 발견되지 않았다.

## Content Model

### Calendar Detail

현재 `data-detail="문장 1|문장 2|문장 3"` 형식을 그대로 사용한다. 설명이 부족한 67개 일정에 아래 항목 중 필요한 내용을 2~4줄로 넣는다.

1. 무엇을 하는 일정이며 다음 일정과 어떻게 연결되는지
2. 초행자가 현장에서 확인할 표지판, 승강장, 입구, 집합 지점 또는 소지품
3. 일정의 핵심 관람 포인트나 음식 선택 기준
4. 지연, 대기, 피로, 악천후 또는 휴무 때 적용할 축소안·대안

각 줄은 일정표 셀의 시간과 충돌하지 않아야 하며, 이미 본문에 있는 정확한 예약·이동 정보를 우선 재사용한다. 새로운 영업시간이나 운행시간을 넣어야 한다면 2026년 7월에 적용되는 공식 출처로 확인할 수 있는 정보만 사용한다.

### Main Guide Text

본문 전체를 일괄적으로 길게 만들지 않는다. 다음 조건에 해당하는 항목만 2~3문장으로 보강한다.

- 공항 도착 뒤 이동처럼 표지판·수하물·환승 행동이 필요한 구간
- 체크인, 짐 보관, 숙소 복귀처럼 다음 일정의 성공 여부에 영향을 주는 구간
- `점심`, `아침식사`, `숙소 복귀`처럼 장소명만으로 행동을 결정하기 어려운 구간
- 비, 지연, 피로 때 무엇을 생략하거나 유지해야 하는지 불분명한 구간

관광지와 식당 설명이 이미 메뉴, 전망, 체류 기준, 대안을 포함하면 중복 문장을 추가하지 않는다.

본문 최소 검토 대상은 다음과 같이 고정한다. 각 항목이 이미 네 가지 기준을 충족하면 문장을 늘리지 않고, 부족한 요소만 추가한다.

- 체코: `KE969 인천공항 → 프라하`, `공항 → Hotel Paris Prague · 체크인`, 마지막 날 `점심`, `수하물 픽업·프라하 공항 이동`
- 스위스: `호텔 → Luzern Station`, `Hotel Luzernerhof 이동·체크인`, `인터라켄 점심`, `호텔 글레처블릭 이동`, `체크아웃·플랫폼 확인`

추가 본문 보강 대상은 문단이 60자 미만이거나 제목이 `점심`, `아침식사`, `숙소 복귀`, `체크인`처럼 일반적이면서 현장 행동 또는 대안이 없는 항목으로 한정한다.

## Files And Ownership

### Czech Content Worker

- 수정: `czech_honeymoon_guide.html`
- 책임: 체코 일정표 42개 누락 상세, 체코 본문의 취약 문구, 체코 내부 시간·장소 일치
- 금지: 스위스 HTML, 공용 지도 데이터, 서비스 워커 수정

### Swiss Content Worker

- 수정: `switzerland_honeymoon_guide.html`
- 책임: 스위스 일정표 25개 누락 상세, 스위스 본문의 취약 문구, 스위스 내부 시간·장소 일치
- 금지: 체코 HTML, 공용 지도 데이터, 서비스 워커 수정

### Cross-Surface Auditor

- 우선 읽기 전용 검토: `assets/map-data.json`, `assets/schedule-detail.js`, `scripts/verify-guide-app-web-ui-cdp.mjs`, `scripts/verify-local-route-maps-cdp.mjs`
- 책임: 상세 누락, 일정-본문 불일치, 장소 키·경로·사진·모바일 검증 항목을 보고한다.
- 편집 작업자와 동시에 체코·스위스 HTML을 수정하지 않는다.

### Administrator

- 체코·스위스 변경을 검토하고 기존 내용 삭제 여부와 예약·시간 변형 여부를 확인한다.
- 일정의 의미가 달라진 경우에만 `assets/map-data.json`의 관련 summary/note를 수정한다. 문장 보강만으로 경로 의미가 바뀌지 않으면 지도 데이터는 변경하지 않는다.
- 콘텐츠가 바뀌므로 `service-worker.js` 캐시 버전을 한 번만 올린다.
- 검증 과정에서 발견된 오류를 수정하고 전체 회귀 검증을 다시 실행한다.

## Data Flow

1. 사용자는 기존 일정표 셀을 누른다.
2. `assets/schedule-detail.js`가 셀의 시간, 제목, 유형, 날짜·도시·숙소 문맥을 읽는다.
3. 새 `data-detail` 문자열이 `|` 단위로 분리되어 상세창의 `세부 구간` 목록에 표시된다.
4. 같은 일정의 본문 설명은 상세창보다 긴 여행 가이드 문맥을 제공한다.
5. 지도 버튼은 기존 `data-route-map-card`와 `assets/map-data.json` 연결을 그대로 사용한다.

## Error Handling And Preservation Rules

- 확정 예약, 항공편, 열차, 숙소, 지도 번호는 재최적화하지 않는다.
- 원본에 있는 일정이나 후보를 설명 보강 과정에서 삭제하지 않는다.
- 상세 내용이 본문과 다르면 본문의 확정 정보에 맞추고, 두 정보가 모두 모호하면 새로운 사실을 추정하지 않는다.
- 시간이 촘촘한 구간에는 새로운 정류장을 추가하지 않고 대기·환승·축소 기준만 설명한다.
- 웹용·앱용 별도 HTML을 만들지 않는다.
- 실제 Google Maps API 키는 로그, 문서, 스크린샷, 커밋에 포함하지 않는다.

## Validation Design

### Static Content Checks

- 체코 46개와 스위스 39개 일정표 이벤트 모두 비어 있지 않은 `data-detail`을 가져야 한다.
- 각 `data-detail`은 2개 이상의 비어 있지 않은 `|` 구간으로 분리되어야 한다.
- `엑셀`, `Excel`, `스프레드시트`, `가져왔` 같은 금지 출처 문구가 가이드 콘텐츠에 없어야 한다.
- `assets/map-data.json`이 파싱되고 20개 일별 지도 ID, 장소 키, 좌표, 경로 참조가 유효해야 한다.
- `git diff --check`와 수정된 JavaScript 구문 검사가 통과해야 한다.

### Browser Checks

`scripts/start-local-server.ps1`로만 로컬 서버를 실행하고, 지도 확인 전 `assets/google-maps-config.local.json`의 HTTP 응답이 `200`, `hasApiKey=true`, route engine `routes`, monthly limit `990`인지 값 노출 없이 확인한다.

다음 12개 조합을 확인한다.

- 체코, 스위스, 이탈리아
- 393×852, 402×874
- `?view=web`, `?view=app`

각 조합에서 가로 문서 넘침, 고정 상단바 겹침, 텍스트 겹침, 토글 유지, 지도 버튼 탭 가능 여부를 확인한다. 체코·스위스에서는 대표 이동·관광·식사·숙소·준비 항목을 각각 열어 상세창 제목, 요약, 세부 구간, 닫기 버튼, Escape 키, 키보드 Enter/Space 동작을 검증한다.

### Regression Loop

검증 실패가 나오면 실패 항목을 파일·날짜·일정명 단위로 기록하고 원인을 수정한 뒤 정적 검사와 12개 브라우저 조합을 처음부터 다시 실행한다. 새 실패가 없고 모든 요구사항을 증명하는 최신 출력이 있을 때만 완료로 판단한다.

## Completion Criteria

- 체코 46/46, 스위스 39/39 일정표 상세가 행동 가능한 세부 설명을 제공한다.
- 기존 일정, 예약, 숙소, 사진, 지도 경로가 삭제되거나 재배치되지 않는다.
- 선별된 본문 취약 항목이 무엇·왜·현장 행동·대안 중 필요한 정보를 제공한다.
- 공유 웹/앱 구조와 지도 20개가 유지된다.
- 정적 검사, 일정 상세 상호작용, 모바일 12개 조합, 로컬 지도 검증이 모두 최신 실행에서 통과한다.
- 검증 중 발견된 오류를 수정한 뒤 전체 검증을 다시 통과한다.
